# Phase 6 — Desktop queue worker

Status: **planned** (not started)

## Goal

I can tap Send to desktop on my phone, lock it, and later find the finished audio in Drive, generated by my desktop.

## Scope

**In this phase**

- App side: **Send to desktop** in the Generate sheet, writing `Queue/<job-id>.json` via `Storage.enqueue`; Queue screen with status, how long pending, last heartbeat; item shows "Queued on desktop".
- Desktop worker (`worker/`, Node 24, Windows): polls `Queue/` every 60 s, claims jobs, generates with Kokoro, encodes MP3 (same encoder settings as the app), uploads to the item's `audio/`, marks `done`. Heartbeat every 60 s while working. Stale-job recovery (no update for 15 min → back to `pending`), done by both the worker and the app.
- System tray icon (status, Pause, Open log, Re-authorise, Quit) and start with Windows.
- Shared code: chunking, speech text, item model and the `Storage` interface are imported by the worker from `src/` so the phone and desktop produce identical files.

**Left for later**

- Multiple workers (supported by the claim protocol, not tested).
- Railway backend.

## Steps

1. [ ] **Spike:** `worker/spike.ts` — kokoro-js in Node with `device: 'dml'` (DirectML on the RX 9070 XT via onnxruntime-node) vs `'cpu'`, measure RTF. Record results in SPEC's benchmark table. If kokoro-js can't use DML, CPU on a 9800X3D is still expected to be several times real time.
2. [ ] **Worker package.** `worker/package.json` (`"type": "module"`), `worker/tsconfig.json`; `npm install kokoro-js@1.2.1 wasm-media-encoders@0.7.0 systray2@2.1.4`; run with `node --experimental-strip-types` or a `tsx@4.x` dev dependency (pinned when added).
3. [ ] **Auth for the worker.** `worker/src/auth.ts`: OAuth "Desktop app" client (a second client ID in the same Cloud project), loopback redirect + PKCE, refresh token stored with Windows DPAPI (via `@primno/dpapi`, pinned when added) in `%APPDATA%\Noteable\token.bin`, **never in the repo**. See the testing-mode 7-day refresh-token issue in the risk list — the Re-authorise tray item exists for that.
4. [ ] **NodeDriveStorage.** `worker/src/NodeDriveStorage.ts`: the same `Storage` interface; shares the request-building code with `src/storage/DriveStorage.ts` (extracted into `src/storage/driveCore.ts`, fetch and token provider injected).
5. [ ] **Queue loop.** `worker/src/queue.ts`: every 60 s list `Queue/`, reclaim stale `working` jobs, `claim` oldest `pending`, run `runChapterJob` (shared), heartbeat every 60 s, `complete`. Resumes chapter-by-chapter like the phone.
6. [ ] **Tray.** `worker/src/tray.ts` with `systray2`: icon colours idle/working/error, menu items above. Logs to `%APPDATA%\Noteable\worker.log` (rotated at 5 MB).
7. [ ] **Start with Windows.** `worker/scripts/install-startup.ps1`: builds, then creates a shortcut in `shell:startup` running `node worker/dist/main.js` hidden (`wscript` launcher). `uninstall-startup.ps1` removes it. (A Windows service can't show a tray icon, so not `node-windows`.)
8. [ ] **App UI.** `src/ui/generate.ts` (Send to desktop), `src/ui/queue.ts` (job list: pending for N min / working on ch X, heartbeat N s ago / done / failed with message, Cancel for pending jobs).
9. [ ] Commit, deploy app; update this document. Worker is run from the repo on the desktop (no installer).

## Tests

- **Unit:** claim protocol with two simulated workers racing; stale reclaim at 15 min; heartbeat; job file schema validation; cancellation.
- **Integration:** worker against the real Drive with a throwaway `Noteable-test/` root (configurable root name), 2-chapter job end to end.
- **Soak:** leave the worker running overnight with the tray icon; check log, memory.

## Gate

> Done when: Send to desktop from the phone produces audio while the phone is locked.

1. On the desktop, run `worker/scripts/install-startup.ps1` once (I'll give the exact command), sign in when the browser opens, and confirm the tray icon is green ("Idle").
2. Reboot the desktop and confirm the tray icon comes back on its own.
3. On the S23, import a markdown file of about 10 minutes, tap **Generate** → **Send to desktop**.
4. Lock the phone and put it away.
5. Within about a minute the tray icon turns to "Working".
6. After it finishes (tray back to Idle), unlock the phone, open Noteable → **Queue**: the job shows **Done**.
7. Play the item on the phone; check the MP3s in Drive.
8. Stale check: send another job, quit the worker from the tray mid-job, wait 15 minutes, start the worker again: the job is reclaimed and finishes without regenerating finished chapters.
